# Signal Processing and Machine-Learning Kernels: Roadmap

Status: **agreed direction** (2026-11-22). Vectrix will be the numeric kernel library for signal processing, and
for a neural-network / LLM library the project will build separately.

The ownership rule is the one used for IK and physics (see `Dynamis/docs/architecture/math-gpu-ownership.md`):
**vectrix holds the pure numeric kernels over flat data; the consuming library holds the data model and the
policy.** For neural networks this means:
- **In vectrix:** forward and backward kernels.
- **In the NN library:** tensors (shapes, strides, views), the autodiff graph, layers, models, training loops,
  tokenizers, model formats, scheduling and GPU execution.

## Decisions

| Topic | Decision |
|---|---|
| Storage | Every kernel accepts off-heap `MemorySegment`s (needed above 2³¹ elements and for memory-mapped weights), with array overloads for convenience. |
| Threading | Kernels are single-threaded. They offer tiled entry points so the caller can parallelize; scheduling is the caller's policy. |
| Determinism | Results are bit-identical across platforms and thread counts by default. Reductions use a fixed order and a fixed tile size (never per-thread chunks), combined in a fixed order. Vectorized transcendentals are vectrix's own polynomials, with documented error bounds, not the JDK's platform-dependent intrinsics. |
| NN library | A separate repository that depends on vectrix. It will be created later; its interface is settled when it exists. |
| Order | Signal processing first, starting with the FFT rebuild; then the NN core kernels. |

## Thread-safety contract

- **No hidden state:** kernels are static and never retain references to caller data, so concurrent calls are safe.
- **Shareable precomputation:** plans and tables (FFT twiddles, window tables) are immutable after construction and
  can be shared by any number of threads.
- **Caller-owned buffers:** scratch and output buffers belong to the caller, one scratch buffer per thread.
  Concurrent reads of a shared input are safe. The caller must not let two threads write overlapping output
  regions.
- **Deterministic tiling:** tiled entry points work on disjoint output tiles. Because tiles have a fixed size, the
  result does not depend on how tiles are assigned to threads.

## Where things stand (inventory, 2026-11-22)

| Area | Exists | Gap |
|---|---|---|
| FFT (`fft`) | In-place radix-2 complex FFT; FFT convolution (before the 2.5.0 rebuild) | Twiddles are generated by recurrence, so the error grows with n: measured 6e-15 at 2¹⁰ points, 7.8e-12 at 2²⁰. It takes 118 ms for 2²⁰ points (a good Java FFT is about 15–20 ms), handles powers of two only, has no real-input transform, and convolution allocates. |
| SIMD | Vector API paths (culling, transforms); the `-simd` jar | — |
| Linear algebra | Cholesky, LDLᵀ, QR, least squares, 3×3 eigen, SVD, polar | No GEMM/GEMV and no BLAS-1 operations. |
| Number formats | fp16, unorm/snorm, packed GPU formats | No bf16, fp8 or block int8/int4. |
| Randomness | PCG hash, Sobol, Halton, R2 | No counter-based generator (Philox) for reproducible dropout and initialization. |
| Transcendentals | Scalar `AccurateMath` | No vectorized `exp`/`log`/`tanh`/`erf` with error bounds. |

## Signal processing

1. **FFT rebuild** (done in 2.5.0: `ComplexFft`, `RealFft`, `ComplexFft2`, `RealFft2`, `BlockConvolver`; the
   remaining work is small-size butterflies and a Vector API path, since below 4,096 points the plans are only
   1.3–1.4× faster than the old code):
   - immutable plans holding exact precomputed twiddles, for error O(ε log n);
   - cache-friendly passes;
   - complex and real-input transforms;
   - any size (radix 2/3/4/5 and Bluestein);
   - 2D transforms;
   - caller scratch, with no allocation;
   - streaming convolution (overlap-add; overlap-save offers no advantage with caller-held state);
   - float and double twins;
   - `MemorySegment` overloads.
2. **Filters and spectra:**
   - window functions (Hann, Hamming, Blackman, Kaiser, Dolph–Chebyshev);
   - FIR design;
   - IIR biquads in transposed direct form II, with caller-held state;
   - polyphase resampling;
   - STFT and ISTFT;
   - DCT-II/III and MDCT;
   - Goertzel;
   - the Hilbert transform;
   - Welch PSD;
   - cross-correlation.
3. **Later, if needed:** wavelets and Kalman filter steps.

The first consumer is DynamisAudio.

## Neural-network / LLM kernels

1. **Core:**
   - GEMM/GEMV (blocked and vectorized);
   - BLAS-1 operations;
   - deterministic reductions (pairwise or compensated sums, norms);
   - softmax, log-softmax and log-sum-exp;
   - layer norm and RMS norm, with backward passes;
   - ReLU, GELU, SiLU and softplus, with backward passes;
   - cross-entropy;
   - rotary position embeddings, which need accurate sin/cos at large positions.
2. **Formats:**
   - bf16 and fp8 (E4M3/E5M2);
   - block-quantized int8/int4;
   - quantized GEMV with fp32 accumulation.
3. **Attention and training:**
   - attention with an online softmax;
   - masks;
   - SGD and AdamW steps;
   - gradient clipping;
   - Philox-based dropout and initialization;
   - top-k, top-p and temperature sampling.
4. **Later:** convolution and pooling layers.

The CPU kernels also serve as reference implementations for GPU versions in DynamisGPU.
